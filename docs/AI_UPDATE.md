# 更新与 AI 协助更新指引

本项目是 Windows 本机应用，浏览器是界面。更新程序必须保留使用者自己的数据库、附件和配置。

## 更新前

1. 确认目录是本人的工作台，读取 `workbench/db.py` 中 VERSION 和 SCHEMA；运行中可读取本机 `/healthz` 确认工作区身份。
2. 在工作台“导出与备份”创建并下载完整备份 ZIP。分析 ZIP 不能用于恢复。
3. 记录数据库、引用原件、岗位和资料数量，保护本地未提交修改。
4. 退出启动窗口中的服务。不能把关闭浏览器当作停止服务，不能根据端口号随意结束其他进程。

## 获取并应用更新

- 只从本仓库明确版本获取代码，先查看版本变化与数据结构兼容要求。
- Git 用户在工作区干净时可 `git pull --ff-only`；存在本地修改时先保留并审查，不自动执行 `reset --hard` 或清除文件。
- ZIP 用户保留旧目录，更新经过审查的程序文件；保留整个 `data/` 及完整备份。不能用新的空白 `data` 替换原有数据。
- 用项目 `.venv` 安装 `requirements-lock.txt`，再通过启动器运行。不要复制别人的 `.venv` 或 `config.local.toml` 来覆盖本机环境。
- 当前 v1.1.2 使用 schema 5；支持结构 1–4 经完整迁移前快照升级，旧代码不能写入结构 5。未来版本必须以其实际代码和更新说明为准，不能把本段当永久兼容承诺。

## 更新后验证

确认应用／结构版本和工作区身份，核对更新前已有的业务记录和原件。打开岗位详情、简历或资料预览，检查完整备份可生成。需要新增数据测试时使用隔离目录，不能把测试岗位混入真实工作区。

如迁移失败或发现数据差异，保留当前数据与错误日志，停止继续写入并说明差异；不能自动用旧快照覆盖新增资料。Git 代码回退和业务恢复分别处理，恢复预览后仍需由使用者确认覆盖范围。

## 可直接给 AI 的提示词

> 请依据个人求职工作台仓库的更新说明，把我本机的工作台更新至我指定的版本。先确认实际工作区和当前版本，生成并验证完整备份，保留本地修改，再停止已确认身份的工作台服务。审查新版兼容性，只更新程序及依赖，保护整个 data 目录。启动后核对工作区身份、已有业务记录和原件，报告版本与检查结果。不要删除数据库，不要清除忽略文件，不要把旧业务快照自动覆盖当前资料；恢复数据前向我说明实际覆盖范围。若我没有指定目标版本，请先说明可用版本供我选择。
